Remote backup (NAS / another server)

VPN configuration

Upload the client file from your VPN server (.conf for WireGuard, .ovpn for OpenVPN). It is stored readable by root only. The VPN connects only for the copy, then disconnects; only traffic to the NAS goes through it, so access to this server is never cut off.

SSH key

The panel logs in with a key (no password stored). Click Install key and enter the NAS password once: it is used one time to install the key and is not saved. Or paste the public key below into the NAS user's ~/.ssh/authorized_keys yourself. The NAS needs SSH and rsync enabled (Synology: Control Panel > Terminal and SNMP > SSH, and File Services > rsync).

Health check:

Runs automatically before and after every GLPI update: if a critical check fails after the update, GLPI is rolled back from the backup. Warnings never roll back. Tip: record the public domain with echo your.domain.ie > /opt/glpi/<name>/.domain to also test HTTPS and the SSL certificate.
Add a new GLPI instance (e.g. another school)
Creates /opt/glpi/<name>/ with its own GLPI + MariaDB containers, volumes, random passwords and a free local port, installs an empty GLPI database and shows it in this panel. It joins the nightly backup, retention and NAS copy automatically.

Stored in /var/backups/glpi/<name>/: database, /var/glpi (incl. glpicrypt.key), plugins and compose files.
Server backup (websites, system, CyberPanel settings, databases)
Backs up the websites (/home), system files (/etc, cron, OpenLiteSpeed config), CyberPanel settings and every MariaDB database (one dump per database, so one website can be restored alone). It runs in the daily job after the Docker backups and is copied to the NAS with the same remote/VPN settings (folder _server). Docker containers and GLPI are backed up by the other tabs.
